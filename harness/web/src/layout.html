      For a program

      An agent or a script can edit the layout here without guessing at the page.

      • Every control names what it edits. data-path is the JSON pointer of its value (/rank/known, /keys/KeyA/base/t). A button that adds something has data-add, one that removes data-remove, a form's chooser data-form, a key's layer chooser data-state, a key on the keyboard data-code. The words under a field are its description from the schema, then its pointer, its limits and whether it is required.
      • The file is in the page, always current: <script type="application/json" id="bada-layout">. What is wrong with it is the list #problems, each item with data-problem.
      • window.badaLayoutEditor does everything the controls do: schema, get(path), text(), set(path, value), remove(path), setRead(read), load(objectOrText), start("stock:ja-romaji" | "mine:<id>" | "new:<read>"), sources(), describe(path), fields(path), places(), blank(path), status(), save(), unsave(), undo(), reveal(path), type("KeyG", "KeyK", "shift+KeyS"), clear(). describe answers for a place the file doesn't have yet, so ask it before you set. status() returns {ok, format, engine}: the schema's problems and the engine's.
      • The schema is layout.schema.json (JSON Schema 2020-12), with a description of every field. layout.html?from=stock:ko-2-set starts from a layout by its address.
      • <html data-ready="true"> once the engine has loaded.
